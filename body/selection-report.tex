\chapter{选题报告}\label{chap:selection-report}

\section{选题依据}

\subsection{研究来源}

本课题来源于前期智能体运行可观测性原型实践和相关文献研究。现有原型可以通过运行日志、时间线和结构视图展示模型消息、工具调用、请求信息与部分上下文来源。但开发者在实际排查中，仍需要在多个视图之间手工判断某个运行现象与哪项运行框架机制有关，以及当前判断由哪些证据支持。本研究即由这一实践问题展开。

\subsection{研究背景}

大语言模型智能体（large language model agent，以下简称智能体）正从单轮问答工具发展为能够调用外部工具、访问工作环境、维护上下文并连续执行任务的复合系统。它的行为由基础模型与一系列运行基础设施共同塑造，包括执行环境、工具接口、上下文与记忆、生命周期编排、可观测、验证评估和治理安全。这组围绕模型、将任务组织成可执行过程的设施通常称为智能体运行框架（agent harness，以下简称运行框架）。当任务链条变长时，开发者除了判断最终结果是否正确，还需要找出结果在哪一步开始偏离，以及哪项运行机制值得继续检查。

现有评价工具可以报告任务成功率、基准得分、成本与延迟，却不一定能将这些结果转化为具体的系统修改。van der Maden等人\cite{ref01}对19名生产环境中的大语言模型产品实践者进行访谈，其中17人遇到了“结果与可行动性鸿沟”：团队能够收集分数和反馈，但难以判断问题来自提示组织、检索、工具、上下文还是其他系统环节。智能体运行轨迹通常混合了自然语言生成、工具调用、环境反馈和中间状态变化。早期异常可能在后续步骤中传播，直到最终以错误输出或提前终止的形式显现。

部分技术研究已经尝试将原始轨迹组织为数据流、控制流与实现锚点，再用于故障归因和运行框架修复。HarnessFix\cite{ref20}通过面向运行框架的轨迹中间表示（Harness-aware Trace Intermediate Representation，HTIR），将运行步骤与提示模板、工具规范、配置项和验证脚本等实现对象对齐，并在四类基准上将初始框架表现提高6.3至18.4个百分点。这一结果说明，轨迹与运行机制的关联具有实际工程价值。但该方法主要服务于自动诊断和修复模块，其输出仍需要核查。Zhang等人\cite{ref03}在自动故障归因研究中发现，最佳方法对责任智能体的识别准确率为53.5\%，对具体步骤的准确率仅为14.2\%。

另一类研究通过时间线、层级视图、断点、回放和现场编辑帮助用户观察或干预运行过程。AGDebugger\cite{ref02}、AgentStepper\cite{ref18}和AgentGUI\cite{ref13}的实验显示，结构化轨迹可以缩短部分定位任务的用时，并提高特定缺陷的识别率。但是，界面中的原始记录、规则推导和模型生成的候选解释常被放在相近的视觉层级。当一条连线出现在关系图中，用户可能将其解读为已经证明的因果关系。例如，日志中存在某条工具结果，只能证明该结果已经产生；若缺少后续模型请求的完整快照，便不能断言该结果已被模型读取。静态结构图中的连线也可能仅表示预设架构，而不是当次运行真实经过的路径。

因此，本研究将对象限定为智能体运行框架的运行理解：开发者如何将一次运行中的现象与发挥作用的运行机制建立联系，并说明这项判断的证据根据。研究进一步聚焦上下文构造与变换，关注信息从何处进入模型请求、在后续步骤中如何被保留、替换、裁剪或摘要，以及现有记录能否支持某项故障判断。这一范围保留了运行框架问题的代表性，也便于为实验材料建立客观真值。

\subsection{研究目的及意义}

本研究拟建立一种面向开发者运行理解的轨迹与机制关联方法，并在界面中明确呈现关联的证据状态。研究首先通过真实运行案例与形成性研究，识别开发者在追踪上下文来源、判断信息变换和定位故障时的证据需求及常见误判。随后，在既有运行架构原型上，将数据流、控制流与实现锚点组织为可下钻的关联视图，并将每项关系标记为“实际记录”“规则推导”或“目前未知”。最后，通过具有客观真值的三条件受控实验，比较关联组织和证据状态对理解正确性、证据定位、完成时间与无依据结论的影响。

在理论层面，本研究将传统程序调试中的“为什么”与“为什么没有”提问、信息觅食和层级排故研究，延伸到由自然语言生成、工具交互与运行时上下文共同构成的智能体系统。研究将数据—框架理论（Data–Frame theory）用于解释开发者如何在轨迹证据与机制假设之间修正理解，并将“无依据结论”纳入运行理解质量的评价。证据状态作为独立界面变量，还可用于讨论直接记录、规则推导与未知边界如何影响用户的结论校准。

在实践层面，本研究希望为智能体可观测与调试工具提供可以验证的交互设计依据。研究重点不是继续增加日志字段，而是考察既有证据如何被组织、核验与限定。预期产出包括可复用的运行理解任务、明确标记证据状态的轨迹与机制关联原型、受控评价方法和相应设计建议。这些成果可供智能体开发平台、可观测工具与自动诊断系统的人机界面参考，帮助开发者在找到关键证据的同时，对证据不足的问题保留判断。

\section{研究问题与方法}

\subsection{研究问题}

本研究考察一次智能体运行已经发生、系统暂不进行自动修复的情形。研究对象不是日志字段的数量，而是开发者能否利用运行记录形成可检查、可说明依据且保留未知边界的机制理解。根据前述研究现状与不足，本研究提出以下问题：

\textbf{研究问题一（RQ1）}：开发者在理解智能体运行框架的执行过程与定位故障时，需要哪些跨步骤、跨组件的证据关联？现有原始轨迹与静态结构视图在哪些任务中会导致证据难以定位、连线被误解或推测被当作事实？

\textbf{研究问题二（RQ2）}：在底层运行记录相同的条件下，将分散事件组织为数据流、控制流与实现锚点的轨迹与机制关联，能否提高运行理解正确性和证据定位准确率，并缩短定位时间？

\textbf{研究问题三（RQ3）}：在已经呈现轨迹与机制关联的基础上，进一步标明“实际记录”“规则推导”和“目前未知”三类证据状态，能否减少参与者在证据不足时作出肯定判断，并在任务负担可接受的前提下改善结论校准？

\subsection{研究方法}

本研究采用“形成性研究、原型设计、受控评估”的混合研究路径。第一阶段识别开发者的实际困难并形成运行理解任务集；第二阶段将发现转化为设计要求，并实现关联界面原型；第三阶段通过条件隔离的实验分别检验关联组织与证据状态的作用。三个阶段使用同一组核心概念和可追溯的材料链，使形成性发现、界面机制与实验指标之间建立明确对应。

\subsubsection{第一阶段：形成性研究}

第一阶段拟招募8至12名具有智能体开发、调试或高频使用经验的参与者。研究材料由预先采集的真实运行记录和少量仪器化构造案例组成，覆盖三类情形：某条约束、历史信息或检索材料的来源难以确定；信息经压缩、裁剪或替换后是否仍出现在后续请求中；工具输出是否被保存、转换并进入了模型实际读取的输入。

参与者将使用原始轨迹和现有架构视图（Architecture view）完成排查任务，并在操作过程中进行出声思考。研究记录其导航路径、视图切换、证据选择、假设变化、放弃点与最终结论，任务后进行半结构化访谈。定性材料采用反思性主题分析，并以数据—框架理论中的框架形成、扩展、质疑、比较与重构作为辅助分析概念，同时允许新的困难类型从材料中产生。本阶段将形成困难清单、运行理解任务集、证据需求清单和初步设计要求。

本阶段还设置继续条件，以避免将视觉偏好误当作稳定研究问题。只有当某类证据困难在多名参与者或多个案例中重复出现，并实际影响答案正确性时，才将其转化为正式原型需求。若反馈主要是视觉样式偏好，且未发现稳定的证据困难，则需要缩小研究范围或重新构造任务，不直接进入正式评估。

\subsubsection{第二阶段：关联界面原型设计}

第二阶段在现有运行架构原型上进行迭代。原型保留固定运行结构、会话与轮次及步骤联动、上下文构成与运行链路并列等现有功能，新增轨迹与机制关联、证据状态和双向下钻三项机制。

轨迹与机制关联使用数据流表示信息来源、传递、变换与消失，使用控制流表示重试、委托、校验与终止等运行决策，并用实现锚点将运行证据连接到提示模板、工具规范、配置项、上下文处理函数或验证脚本。每项关联同时标明证据状态。实际记录的关系必须能够返回原始事件；规则推导的关系需展示其输入、规则和适用前提；目前未知的关系则说明缺少哪类信号以及可能的补证方式。双向下钻支持用户从异常现象进入相关机制，也支持从系统结构返回具体运行事件。

原型开发将建立“形成性发现、设计要求、界面机制”对应表。每项核心交互需标明它回应了第一阶段的哪类困难，并在第三阶段中对应至少一个客观指标。原型将先经过专家走查和小规模可用性预测，检查术语理解、状态识别、跨视图选中与返回原始证据等问题，修订后再进入正式实验。

\subsubsection{材料构建与客观真值}

运行理解必须有可核对的标准答案，否则只能评价参与者的主观清晰感。本研究将真实运行记录与仪器化构造案例结合使用。真实案例保留长轨迹、噪声和不完整数据等实际特征；构造案例则有计划地操纵上下文保留、替换、裁剪、摘要与工具结果注入等机制，使关键问题具有明确答案。

每个案例都将建立独立的证据清单，记录原始事件、稳定标识、关联规则、实现位置与不可观测边界。两名研究者依据统一手册独立标注，并报告评分者间一致性；有分歧的案例经讨论后修订，无法形成可复核标准的案例予以剔除。“目前未知”同样需要明确依据：只有当必需信号确实未被记录、被采样排除或超出观测边界时，才作出该标记。这一过程既用于建立实验真值，也为界面中的状态说明提供数据基础。

\subsubsection{测量与数据分析}

第三阶段的主要因变量包括运行理解正确率、证据定位准确率、完成时间和无依据结论率。运行理解正确率衡量参与者对事件来源、变换机制与故障位置的判断是否与客观真值一致。证据定位准确率衡量其能否找到支持结论的轨迹片段与实现锚点。无依据结论率统计参与者在证据不足时仍作出肯定判断，或将规则推导误述为直接事实的比例。辅助指标包括导航路径、视图切换、答案修改、原始任务负担指数（Raw NASA-TLX）与主观可用性评价。

量化数据将在试次层面采用混合效应模型分析。界面条件和任务类型作为固定效应，参与者和材料作为随机效应。二值结果使用广义线性混合模型，连续结果根据其分布选择线性混合模型或稳健方法。主要比较为A与B、B与C，分别对应轨迹与机制关联和证据状态呈现的增量作用。样本量将根据预测得到的效应量与随机效应方差，通过模拟功效分析确定，不预先套用既有研究的固定人数。交互日志、屏幕记录和访谈材料用于解释界面未提供线索、参与者未发现线索和发现线索后仍然推断错误三种情况。

\subsubsection{可行性与伦理}

本研究已具备运行记录、文献基础与运行架构原型，可以在不搭建在线自动修复平台的条件下开展研究。材料来自公开框架、自有原型和预先采集的运行记录，不使用企业内部数据。涉及参与者的研究将在取得伦理审查批准后实施。参与者需完成知情同意，可在任意时点退出。数据将以研究编号替代身份信息，屏幕记录和访谈转录经去标识后分析。正式收集数据前，第三阶段的研究设计、主要指标和分析计划将进行预注册；在不泄露个人信息的前提下，开放任务材料、评分手册和分析代码。
