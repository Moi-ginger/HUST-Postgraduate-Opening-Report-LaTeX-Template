## 一、调研范围与核验程度

本次从原稿涉及的关键研究出发，重新检索程序调试、智能体失败归因、交互调试、信息溯源、不确定性及设计研究方法。优先使用论文原文、出版机构页面、作者或研究机构存档；网络检索用于发现文献，再回到上述来源核查。没有把工具宣传页和二手综述当作实验结果的直接依据。

检索围绕以下问题组织：LLM agent debugging 与 developer diagnosis；information foraging 与 debugging representations；trace provenance 与 uncertainty；research through design、intermediate-level knowledge 与 design study rigor。对高度相关论文继续追踪题名、参考文献、发表信息及版本。

这是一轮针对选题的文献调研，不是按照完整数据库检索与筛选协议完成的系统综述。不报告未经记录的检索命中数、排除数或 PRISMA 流程。检索整理了 27 篇候选文献；当前两份正文共引用 21 篇不同文献，文献综述与选题报告各引用 17 篇。并非全部文献均逐页精读：对直接影响创新判断及实验解释的近期工作检查了可访问全文的相关章节；对其他文献主要核对原始来源的摘要、相关段落及书目信息。正文据此控制细节和结论范围。

本地文件只读取和产出 Markdown。网页论文以可提取的文本作为调研材料，未下载 PDF、BibTeX 或其他文件。

HarnessFix 的版本差异需要特别保留。初次查阅的 v1 与随后核对的 v2 对表征结构的描述不同。v2 明确设有数据流、控制流和实现锚点章节，因此原稿对这三项能力的概括有文献依据，不能把它判成错误引用。需要调整的是创新归属与适用范围：这三项结构不能再单独充当本课题的新概念，其自动分析效果也不能替代开发者研究。最终正文已使用 v2。

AgentStepper 的摘要和正文对一般理解成绩的统计名称并不完全一致；缺陷识别分析又排除了一位具有既往经验的参与者，任务实例与参与者人数不能混用。本次正文保留研究方向与限制，不复述容易脱离条件的效果数字。[原文](https://arxiv.org/html/2602.06593v1)

## 三、为什么这样重写

原稿已有真实问题、形成性研究、原型探索和对照评价，保留这些组成部分是合理的。根本调整发生在它们之间的关系：形成性研究需要决定什么问题最值得解决，设计探索需要比较不同思路，评价需要支持或修订知识主张，不能只为已经确定的功能寻找需求和正面效果。

| 原稿内容 | 独立判断 | 新稿处理 |
| --- | --- | --- |
| 开发者难以理解分散的长链路运行材料 | 研究起点成立，需要实证确认具体困难 | 保留，作为访谈和任务观察的起点 |
| 意义建构等理论已有讨论 | 主要问题是用途和解释层级不清 | 分别用于查找、表征协调和判断修订，不再拼成预定认知流程 |
| 形成性研究之后才制作原型 | 方向正确，但后续功能已经预先锁定 | 增加选定核心问题的决策环节，允许改变原型方向 |
| “记录—推导—未知”三分 | 来源与可回答性混在同一分类中 | 分开处理信息获得方式及其对具体判断的充分性 |
| 轨迹—机制关联 | 是可研究的设计思路，不能仅凭命名构成理论贡献 | 作为候选方案，承认相近技术已有研究 |
| A/B/C 递进实验 | 可评价系统增量，难以自动解释所有组成部分的独立作用 | 聚焦一个主要问题和两个条件，逐项核对信息内容 |
| 用注入故障作为正确答案 | 可以建立故障事实，但不保证可见材料足以推出答案 | 分别制定实际故障说明与可见材料下的判断标准 |
| 理解、正确性、信心和负担等指标 | 已有价值，但指标过多会分散核心结论 | 设主要诊断结果，其余用于解释作用与代价 |
| 设计原则作为最终成果 | 目标可行，提炼过程不足 | 增加跨案例依据、备选方案比较和新案例边界检验 |

新题目保留对象、任务和设计学关注点，不把尚未得到支持的解决方案写入标题。预期贡献确定为具有适用条件的设计知识；这与导师要求的“能处理一类相似问题”相符，但不保证研究开始前就能宣布发现了新理论。
